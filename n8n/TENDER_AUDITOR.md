# Tender Autofill Quality Auditor

Файл workflow: `Tender Autofill Quality Auditor.json`.

## Назначение

Workflow принимает один или несколько CSV-файлов существующего Finalizer и формирует
отдельный CSV только с подозрительными результатами. Он не изменяет
`tender_autofill_jobs`, не запускает retry и не обновляет `result_json`.

## Настройка после импорта

1. Импортируйте JSON в n8n.
2. В обеих PostgreSQL nodes выберите credential той же базы, где находятся:
   - `tender_autofill_jobs`;
   - `tender_autofill_job_runs`;
   - `tender_autofill_job_events`.
3. В нодах «Chat Model — первичный аудитор» и «Chat Model — аудитор» проверьте
   OpenAI-compatible credential `OpenRouter прокси` и модель
   `deepseek/deepseek-v4-flash-0731`. При необходимости выберите другие модели вручную.
4. Откройте Form URL ноды «Загрузить CSV для аудита» и загрузите CSV Finalizer.

## Как ограничивается контекст

- Первый SQL выполняется один раз по списку Seldon ID. Он не возвращает полный
  `result_json`, но передаёт компактный список названий товаров для поиска дублей,
  адресов и получателей, ошибочно извлечённых как товары.
- Детерминированная нода только добавляет метки и не отбрасывает строки.
- Первый `Loop Over Items` с `batchSize=1` отправляет в первичный AI Agent каждый
  tender из CSV. Логи и данные разных тендеров не смешиваются.
- Кандидаты подробного аудита формируются по правилу
  `deterministic OR первичный LLM OR операционная ошибка`.
- Второй `Loop Over Items` запрашивает полный компактный контекст отдельно для
  текущего `record_key`. Подробный AI Agent получает вердикт CSV, результат первого
  аудитора, товары, result_json и timeline только этого тендера.
- Передаются максимум 60 товарных позиций и 60 последних timeline-событий;
  evidence и requirements дополнительно обрезаются.
- Binary и полный текст документов в LLM не передаются.

## Результат

Финальная binary-нода создаёт `tender_autofill_audit_YYYY-MM-DD.csv`.
Файл можно скачать из execution. В нём находятся исходный статус, найденные
противоречия, вердикт аудитора и рекомендуемые статус/причина.

Вердикт является рекомендацией. Workflow намеренно не исправляет production-данные
автоматически.

## Доступ PostgreSQL

Предпочтительно использовать отдельного read-only пользователя с правом `SELECT`
на три таблицы аудита и jobs. Все SQL-запросы workflow параметризованы; LLM не
генерирует и не выполняет SQL.
