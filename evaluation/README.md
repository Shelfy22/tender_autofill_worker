# Эталон качества подбора

Эта папка предназначена только для офлайн-проверки качества. Рабочий pipeline не
читает эталон, не подмешивает его в промпты и не ограничивает им ассортимент.
Поэтому набор из 100-200 размеченных позиций не ухудшит подбор товаров из других
категорий.

## Где хранить данные

- `golden_dataset.template.jsonl` - обезличенный пример формата.
- `golden_dataset.local.jsonl` - рабочий набор компании. Он исключён из Git.
- `results/` - локальные отчёты прогонов. Папка исключена из Git.

Одна строка JSONL соответствует одной исходной позиции тендера. Не склеивайте все
характеристики в один текст: храните их отдельными объектами с названием, значением
и источником. Для выбранного сотрудником и фактически поставленного товара обязательно
укажите стабильный `ID товара` каталога и, по возможности, артикул.

Несколько допустимых аналогов можно записать в `catalogProductIds` и `articles`.
Если подходящего товара в каталоге действительно нет, используйте
`"outcome": "not_found"`.

`mustContainSearchTokens` задаёт признаки, которые должны попасть в поисковый запрос.
`mustNotContainSearchTokens` полезен для сроков, количества и характеристик, ошибочно
привязанных от соседней позиции. Эти поля необязательны.

## Как собирать набор

Начните с завершённых тендеров, где сотрудник подтвердил подбор и товар был поставлен.
Факт поставки - сильная метка, но замену по наличию или цене помечайте в `notes` как
аналог, а не как единственно технически верный товар.

В наборе нужны не только простые совпадения. Добавьте повторяющиеся названия,
характеристики в отдельном документе, конфликтующие документы, таблицы с объединёнными
ячейками, позиции без характеристик, допустимые аналоги и реальные случаи
`Товар не найден`. Смотрите метрики отдельно по `categoryCode`: общий высокий процент
может скрыть плохую работу на редких категориях.

## Запуск

```powershell
.\.venv\Scripts\python.exe scripts\evaluate_product_matching.py `
  --gold evaluation\golden_dataset.local.jsonl `
  --predictions path\to\tender-result.json `
  --output evaluation\results\baseline.json
```

Основные метрики:

- `positionLinkRate` - сколько эталонных позиций удалось однозначно связать с результатом;
- `top1Accuracy` - доля верных финальных товаров;
- `falseNotFoundRate` - доля найденных сотрудником товаров, для которых ИИ ответил
  `Товар не найден`;
- `wrongMatchRate` - доля неверно выбранных товаров;
- `requiredSearchTokenRecall` - попали ли важные характеристики в запрос;
- `forbiddenSearchTokenLeakRate` - попали ли в запрос запрещённые признаки.

Для устойчивого сравнения не меняйте старые метки после каждого релиза. Ошибки разметки
исправляйте отдельно, а новые случаи добавляйте как новые строки.
